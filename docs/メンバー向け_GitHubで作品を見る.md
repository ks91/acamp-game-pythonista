# GitHubで班のゲームを見る：やさしい見方

GitHubは、班のゲームづくりの「作品ノート」です。難しい操作を覚えなくても大丈夫です。

## 最初に見る場所

Lunaが「できた」と言ったとき、GitHubのリンクが出ることがあります。そのページでは、まず次の三つだけを見ます。

1. **タイトル** — 今回、何を作った・変えたのか。
2. **Files changed** — 前の版と比べて、どのファイルのどこが変わったのか。
3. **レビューコメント** — スタッフやHermesが「よいところ」「直した方がよいところ」を書く場所。

赤い行は以前の版からなくなった部分、緑の行は新しく増えた部分です。全部を読めなくて大丈夫です。気になる場所を一つ選びます。

## 班ができること

- 自分たちのゲームの画面・文章・クエスト案を見る
- 「ここは何をするコード？」とLunaに聞く
- レビューコメントを子ども向けの言葉にしてもらう
- 直したいことをLunaに伝える
- 動いたかどうかをiPadで試し、結果を伝える

## 班がしなくてよいこと

- Gitのコマンドを打つ
- branchやPRの意味を暗記する
- `main` を直接変更する
- マージする
- AWS・トークン・`config.py`を開く

Lunaが班の作業場所で、保存・テスト・レビュー依頼まで担当します。最終的に共通ゲームへ入れる判断とマージはスタッフが行います。

## Lunaへの頼み方

GitHubリンクを貼って、普通の日本語で聞けます。

```text
このページで、私たちが変えたところを小学生にもわかるように教えて。
```

```text
このレビューコメントは、どういう意味？
直すなら何をすればいい？
```

```text
この変更で、プレイヤーができるようになったことを三つ教えて。
まだできないことも教えて。
```

```text
この画面のコードで、私たちのアイデアが入っているところを教えて。
```

```text
ここをもっと面白くしたい。次に変える候補を二つだけ出して。
```

## 見る順番

```text
Lunaが作る
→ iPadで試す
→ GitHubで「何が変わったか」を見る
→ Lunaに意味を聞く
→ 班で次の改善を決める
```

GitHubはテストの点数表ではありません。自分たちのアイデアが、どう少しずつ動くゲームになったかを残す観察ノートです。
