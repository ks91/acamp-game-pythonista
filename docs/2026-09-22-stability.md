# 9/22 出発前の安定性確認

## 今回の変更

- red: 攻撃のたびに戦闘 UI を破棄していた処理を変更。通常ターンは既存のボタンと表示を更新する。武器消耗・勝敗確定などの画面更新は `ui.delay` でタップのコールバックの後に実行する。処理中の重複入力と古い画面からの入力は無視し、報酬の二重処理を防ぐ。終了時は位置追跡を停止する。
- yellow: 起動時の自動リセットを廃止し、既存の進行を読み込む。明示的なリセットは共通 API クライアント経由にし、ギャラリーで選んだゲーム・モードを通信に含める。
- 攻撃力・報酬・キャラクター・謎・ゲームルールは変更していない。ただし red の処理待ち（0.05 秒）の間に届いた追加タップはまとめて無視する。

red のネイティブクラッシュは Mac では再現・解消確認できていない。ボタンをそのコールバック内で破棄する経路と毎ターンの再生成を除いた対策であり、根本原因の確定ではない。Pythonista の `ui.delay` の仕様は [公式 UI ドキュメント](https://omz-software.com/pythonista/docs-3.4/py3/ios/ui.html) を参照。

## iPad での短い確認

更新を共有リポジトリへ反映した後、Pythonista を完全終了してから Working Copy でリポジトリ全体を Pull し、同じ連携フォルダを Pythonista で開く。ファイル1個だけをコピーしない。

1. `diagnostics/red_battle_check.py` を実行する。位置への移動は不要。通信・得点登録はせず、テストの HP と持ち物はこの画面内だけで使う。
2. 「素手」でゆっくり押す／連打を試し、勝利後「地図にもどる」。もう一度同じ操作を試す。
3. 「武器」で木の棒を2回使い、ボタンが消えても素手で続けられることを確認。「逃げる」で戻れる。
4. 「敗北」で攻撃し、結果画面から戻れることを確認。
5. 確認用画面を閉じ、通常は `day4_game_gallery.py` を実行。yellow は起動・開き直しで進行が消えないことを確認。「最初からやり直す」は確認のために押さない。

もし再び落ちたら、どの確認ボタンで、途中か結果表示か、Pythonista 全体が終了したかを記録する。ネイティブ原因の特定には iPad のクラッシュログが必要になる場合がある。
